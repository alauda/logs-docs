# Log Component Selection Guide

When installing the Logging module in ACP 4.4 you pick one storage backend per storage cluster. Three backends are available:

- **ClickHouse** (fresh install via **Alauda Container Platform Log Storage Management**) — recommended for high throughput and cost-sensitive retention.
- **OpenSearch** (fresh install via **Alauda Container Platform Log Storage Management**) — recommended when Lucene-style query experience matters. Introduced in ACP 4.4.
- **Elasticsearch** (legacy chart-based **Alauda Container Platform Log Storage for Elasticsearch**) — retained for existing customers upgrading from ACP 4.2 or 4.3; not the recommended choice for a fresh install.

For ClickHouse and OpenSearch the plugin is the same — **Alauda Container Platform Log Storage Management** — and the backend is selected in `PlatformLogForward.spec.externalStorage.type`. Elasticsearch remains its own legacy chart.

This page compares them so you can pick one before you install.

:::warning

- Pick one backend per storage cluster. Do not stack ClickHouse and OpenSearch on the same storage cluster.
- The DevOps product does not currently support archiving Jenkins pipeline execution records into ClickHouse or OpenSearch. If you rely on Jenkins pipeline archival, choose the Elasticsearch backend.
- The ServiceMesh product currently integrates with the Elasticsearch backend only. If you rely on service mesh log integration, choose Elasticsearch.
- The **ClickHouse** backend does not support IPv6-only or IPv6 dual-stack workload clusters.

:::

## Architecture at a glance

### ClickHouse

A columnar database for OLAP workloads. Compresses well, aggregates fast, and pairs cleanly with S3 for tiered cold storage. Trade-off: no inverted index, so keyword search is a `LIKE`-style scan.

### OpenSearch

A distributed search engine forked from Elasticsearch. Inverted-index search over log records; strong ad-hoc query experience with keyword highlighting and faceted queries. Trade-off: heavier per-record storage and more CPU for the same ingest volume.

### Elasticsearch

The original Lucene backend used before ACP 4.4. Same trade-offs as OpenSearch on the ingest side; retained for customers who cannot yet move.

## Feature comparison

| | **ClickHouse** | **OpenSearch** | **Elasticsearch** | Notes |
| --- | --- | --- | --- | --- |
| High availability | Yes | Yes | Yes | |
| Horizontal scalability | Yes | Yes | Yes | |
| Query experience | Weak (SQL only) | Strong (Lucene DSL) | Strong (Lucene DSL) | OpenSearch and Elasticsearch expose Lucene-style search; ClickHouse offers SQL only. |
| Resource usage per ingest unit | Low | Medium | High | Rule of thumb: to sustain 20,000 logs/s you need roughly 3 ClickHouse replicas (2C/4G), or an OpenSearch cluster with 3 master + 5 data (2C/4G + 8C/16G), or an Elasticsearch cluster of similar shape. |
| Ingest throughput per node | High | Medium | Medium | See [Log Component Capacity Planning](./capacity_planning.mdx) for the ACP-tested profiles. |
| S3 tiered storage | Yes (hot / cold via `PLF.spec.clickhouse.tieredPolicy`) | ISM policy on OpenSearch | ILM policy on Elasticsearch | Only ClickHouse can push cold data to S3 as an ACP-managed feature; OpenSearch and Elasticsearch tiering is a self-managed policy. |
| Chinese full-text search | Substring match | `analysis-ik` plugin (**required** for ACP OpenSearch) | `analysis-ik` plugin | The OpenSearch install must include `analysis-ik`; without it the platform's log query page returns 400. |
| Community activity | Growing | Active (Amazon-led fork) | Active (Elastic-led) | |
| Jenkins pipeline archival | Not supported | Not supported | Supported | Choose Elasticsearch if your platform archives Jenkins pipeline records into Logging. |
| ServiceMesh log integration | Not supported | Not supported | Supported | Choose Elasticsearch if ServiceMesh integrates with Logging. |
| IPv6-only workload clusters | Not supported | Supported | Supported | |

## Recommendations

- **You want the most cost-effective backend for large log volume and can accept SQL-only search.** Install **Alauda Container Platform Log Storage Management** and set `PlatformLogForward.spec.externalStorage.type: clickhouse`. Enable S3 tiered storage if long retention drives your storage bill.

- **You rely on Lucene-style keyword search, highlighting, or faceted queries, or you are already familiar with the Elasticsearch DSL.** Install **Alauda Container Platform Log Storage Management** and set `PlatformLogForward.spec.externalStorage.type: opensearch`. Make sure the `analysis-ik` plugin is installed on every OpenSearch node before you apply the PLF.

- **You depend on DevOps Jenkins pipeline archival or ServiceMesh log integration.** Choose the legacy **Alauda Container Platform Log Storage for Elasticsearch** plugin. Follow the ACP 4.3 documentation for the Elasticsearch installation flow.

- **You are upgrading from ACP 4.2 or 4.3 on Elasticsearch and want to move to a supported backend.** See the ACP 4.4 upgrade and migration documentation (delivered separately). The migration path lands on either ClickHouse or OpenSearch based on which target you provision.
