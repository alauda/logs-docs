# Log Component Capacity Planning

The log storage components hold logs, events, and audit records collected from one or more clusters. Estimate your log scale before install and size the storage cluster using the profiles below.

:::warning

- The tables in this chapter are laboratory reference numbers. Provision more resources than the reference numbers, and do not push the collected volume above the profile's throughput.
- Disk baseline for the tables: `6000 iops`, `250 MB/s` sequential read and write, SSD, independently mounted. Weaker disks require a larger profile than the table suggests and additional CPU + memory headroom.
- ACP 4.4 uses Kafka in KRaft mode. No Zookeeper is deployed; the tables in earlier releases had a separate Zookeeper row that no longer applies.
- Older ACP releases ran the Elasticsearch backend with a separate `Lanaya` consumer between Kafka and Elasticsearch. In ACP 4.4 the recommended backends (ClickHouse and OpenSearch) do not use Lanaya; the ingest role belongs to `aggregate-vector`.

:::

## Common components

All backends share these components:

| Component | Where it runs |
| --- | --- |
| `nevermore` | DaemonSet on every collector node. CPU / memory sized by the number of active containers on the node, not by cluster throughput. |
| Razor | Deployment on the storage cluster. |
| `aggregate-vector` | Deployment on the storage cluster (ClickHouse and OpenSearch paths). |
| Kafka | Broker cluster on or near the storage cluster. |

## Sizing notes

- Set `PlatformLogForward.spec.aggregateVector.replicas` and `spec.razor.replicas` to match the profile you deploy. The CRD defaults (`3` and `2`) suit the medium and large profiles; drop them to `1` on a single-node evaluation cluster.
- Raise `spec.razor.resources.limits.cpu` above the profile default when the collector-side buffer grows during traffic bursts and Razor CPU sits at its limit. See [How to size Razor for burst traffic](../how_to/index.mdx) once that page is published.
- Kafka broker sizing is separate from the storage backend sizing. Follow the [Alauda Container Platform Kafka capacity guide](https://docs.alauda.io/kafka/) for broker-side numbers.
